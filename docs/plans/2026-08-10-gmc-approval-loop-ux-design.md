## 1. 目标与非目标

### 1.1 目标

1. 商家在 **把 Feed 交给 Google 之前**，就知道：会不会挂、我们补了什么、还要改什么。  
2. 服装等条件字段尽量 **自动补全到可过机**，且补全能看见、能改、能批量。  
3. Feed 链接 **变体正确 + 币种钉死**；价币种与落地页一致策略不变。  
4. 交付以 **动态 Feed URL** 为主，减少手传旧 CSV。  
5. 敏感词可软化 / 打 `adult`；主图尽量去掉 1688 脏信息，降低拒审与 CTR 差。

### 1.2 非目标

- 不保证 Google 账号一定 Approve（运费、认领、套餐多货币等店外因素仍存在）。  
- 不静默汇率换汇。  
- 不伪造 GTIN。  
- 不做完整短视频工厂、不做供应链选品引擎。

### 1.3 已拍板（沿用总册 §8）

- 尺码默认 **`One Size`**（非 OSFA 对外）。  
- Brand：可读品牌 > 可读店名 > `DEFAULT_STORE_BRAND`；不用域名。  
- 颜色：先抽取，Multicolor 最后；不一刀切。  
- FATAL **仍进 Feed**；界面 **三色灯**，红灯不叫绿通。

## 2. 总体架构

```
Shopify 商品/变体
    ↓
同步 / 生成任务
    ↓
┌──────────────────────────────────────────┐
│ 安检流水线（可带动画）                      │
│  1 标题  2 类目  3 变体属性  4 标识/无码     │
│  5 链接  6 价币种  7 敏感词  8 图片          │
└──────────────────────────────────────────┘
    ↓
AutoFix + Diagnose → QualityReport
    ↓
持久化 Feed（XML/CSV）+ 动态 URL 渲染同一套规则
    ↓
App：三色灯结果页 + 优化日志 + 异常抽屉/工作台 + Feed URL
```

**原则：** 服务端规则是唯一真相；App 只展示与批量改；动态 URL 出站时再跑同一套兜底（避免「下载时一套、URL 另一套」）。

## 3. 分步落地顺序（设计内的「一步一步」）

实现时严格按步，**不要并行塞爆**；每步有可验收标准。本文是总设计，实现计划以后按此切任务。

| 步骤 | 名称 | 交付物 | 验收 |
|------|------|--------|------|
| **S1** | 过审数据内核 | 属性兜底 + 报告数据 + 无码 + 链接变体 + 价币种门 | 生成返回完整 `quality_report`；船袜等有 One Size；币种拦截仍在 |
| **S2** | 结果页三色灯 + 优化日志 | App 文案与列表（可先无动画） | 绿/黄/红文案正确；红灯二次确认 |
| **S3** | 动态 Feed URL 统一出站 | Google 抓 URL = 最新价库存 + 同套 AutoFix | GMC 只配 URL，不再依赖旧 csv |
| **S4** | 安检动画 | 生成中流水线 UI | 扫描四段 + 价值文案 |
| **S5** | 批量抽屉 + 微调工作台 | 右侧分桶 + Magic Bar + 仅自动填表 | 50 条一键 One Size / 改色 |
| **S6** | 敏感词体系 | 词表 + 软化 + `adult` | 命中有日志；可黄/红 |
| **S7** | 图片急迫项 | 去水印/牛皮癣检测与处理管线（可先检测+半自动） | 脏图 WARN/处理；主图策略清晰 |

**依赖：** S2 依赖 S1；S4/S5 依赖 S1–S2；S6/S7 可与 S4/S5 串行，不阻塞 S1–S3。

## 4. 过审数据内核（S1）

### 4.1 属性兜底（全品类框架 + 服装加强）

**通用：**

| 字段 | 空时策略 |
|------|----------|
| `condition` | `new` |
| `availability` | 仅 `in_stock` / `out_of_stock`（由库存推导） |
| `brand` | 按 §1.3 优先级 |
| 无 GTIN | `identifier_exists=false`（见 4.3） |

**服装 / 鞋服 / 配饰（GPC/标题启发）：**

| 字段 | 策略 |
|------|------|
| `size` | 空 → **`One Size`** + AUTOFIX 日志 |
| `color` | 变体 → 标题/描述 LLM/词典抽取 → 仍空黄灯 → 最后 `Multicolor` |
| `gender` | 规则推断，否则 `unisex` 或保持已有 |
| `age_group` | 空 → `adult` |
| `material` | 能抽则抽；抽不到 → WARN（不造假材质） |

**非服装：** 不强制 size/color；走通用规则。

### 4.2 QualityReport 与三色灯（数据合同）

```text
quality_report:
  summary: { autofixed, warnings, fatals }
  autofixed[] / warnings[] / fatals[]:
    { rule_id, field, sku, message, suggestion }
  checklist[]: 店外事项（运费、认领等）
  light: green | yellow | red
```

**亮灯规则：**

- 有 FATAL → **red**  
- 无 FATAL、有 WARN 或 AUTOFIX → **yellow**  
- 仅通过 → **green**  

FATAL 示例：无主图、价≤0、链接不可用。  
WARN 示例：颜色靠兜底、GPC 低置信、疑似脏图域名。  
AUTOFIX 示例：写入 One Size、adult、identifier_exists。

### 4.3 无码通道

- 无有效 GTIN → 强制 `identifier_exists=false`。  
- brand 按 §1.3，**禁止**用 myshopify 域名。  
- 优化日志必须有一条：「已开通无码通道」。

### 4.4 链接变体

- `link` 必须：`https://{店域名}/products/{handle}?variant={ShopifyVariantId}&currency={ISO}`  
- `variant` 使用 **Shopify 数字 variant id**，禁止用内部 SKU 字符串冒充（若历史用了 SKU，S1 纠正）。  
- 去掉已知垃圾爬虫参数；保留/不破坏商家 UTM 的策略：Feed 主链接保持干净，追踪参数由 GMC/广告侧追加（设计偏好）。

### 4.5 价币种

- 沿用 `2026-08-09-price-currency-markets-design`：店币/展示币与目标国一致才生成该国 Feed；钉 `currency`。  
- 金额与 Shopify 展示价一致，禁止静默换汇。

## 5. 结果页与三色灯 UX（S2）

### 5.1 生成结束主界面

```
[灯色徽章] 主文案
绿：可提交 Google — 主按钮「复制 Feed URL」
黄：已自动补全，建议抽查 — 主按钮「打开微调工作台」+「复制 Feed URL」
红：发现 N 个高风险（仍已生成）— 主按钮「先查看高风险」
      次按钮「仍使用 Feed（可能拒审）」→ 二次确认

摘要：自动 N · 警告 N · 高风险 N
[优化日志] [异常抽屉]
Feed URL + 复制
```

### 5.2 优化日志

每条自动动作一行，可筛选 AUTOFIX/WARN/FATAL。  
禁止只显示「生成成功」。

## 6. 动态 Feed（S3）

### 6.1 行为

- 每店每平台每国家：**稳定 HTTPS URL**（已有 durable 路径则强化「唯一推荐入口」）。  
- Google 请求 URL 时：读库/Shopify 最新价库存 → 跑 **同一套** AutoFix/敏感词/链接规则 → 输出 XML。  
- App 文案引导：GMC 添加该 URL + 每日抓取；**不再引导长期使用本地旧 csv**。

### 6.2 缓存

- 短缓存（如 1–5 分钟）防打爆 Shopify；库存敏感可缩短。  
- 设计要点：缓存失效策略写进实现计划，本文只要求「不能脏读超过可接受窗口」。

## 7. 安检动画（S4）

### 7.1 隐喻

汽车出厂检测线，不是转圈 Progress。

### 7.2 生成中

依次高亮四段（可与真实 pipeline 阶段对齐）：

1. 标题清洗  
2. 类目匹配  
3. 变体属性（色/码）  
4. 标识 / 无码 / 价币种  

**文案示例：**

- 「AI 正在清洗 1688 脏数据，降低 GMC 拒审风险…」  
- 「正在检查变体尺码/颜色…」  
- 「正在开通无码通道…」  

### 7.3 与真实进度

动画阶段应尽量映射后端 job 进度；若后端暂无细粒度，允许「时间片模拟 + 结束时对齐真实报告」，但不得在失败时仍播报到绿通。

---

## 8. 批量抽屉与微调工作台（S5）

### 8.1 右侧「异常修正层」常驻抽屉

- **分桶：** 缺 size、缺/兜底 color、无码已开通、高风险 FATAL、敏感词已处理…  
- 桶内多选 / 全选。  
- **Magic Bar：**  
  - 一键 One Size  
  - 一键标准尺码表（若配置）  
  - 「所选颜色改为 ____」回车批量  

### 8.2 微调工作台

- **只列出被自动填充的字段**（减少噪音）。  
- 兜底值高亮。  
- 行内改 + 批量改。  
- 保存后刷新 Feed / 动态 URL 内容。

### 8.3 弹性确认（列表态）

- **场景 A：** AI 提取 → 行内「AI 提取」高亮，悬停可改，默认不打断。  
- **场景 B：** 智能兜底 → 黄标「AI 优化」，进抽屉分桶。

## 9. 敏感词体系（S6）

### 9.1 目标

降低 Adult / Prohibited / Misrepresentation 导致的拒审与封号风险。

### 9.2 组成

1. **可运营词表**（敏感词、软化映射、是否强制 adult）。  
2. **检测范围：** 标题、描述、自定义标签。  
3. **动作：**  
   - 软化改写（例：战术格斗刀 → 户外露营工具）→ AUTOFIX/WARN + 日志  
   - 类目命中内衣等 → `adult=yes`  
   - 极高危无法软化 → FATAL 提示，仍进 Feed（总规则），红灯  

### 9.3 示例类目（词表种子，可扩展）

塑身/情趣内衣、战术刀、部分按摩/成人向器械等。

### 9.4 UX

命中项进优化日志与抽屉「敏感词」桶；商家可见「原文 → 改写」。

## 10. 图片急迫项（S7）

### 10.1 目标（本阶段）

- 降低「脏图上 Google」：中文水印、牛皮癣字、批发站图。  
- 主图尽量干净；白底为 **偏好** 非强制一刀切。

### 10.2 流水线（设计）

```
主图 URL
  → 检测：域名风险 / OCR 中文水印与贴纸（能力可分期）
  → 处理：去水印（已有 image_processor 可复用） / 可选白底
  → 上传可公网 URL（如 R2）
  → Feed image_link 指向处理后地址
  → 失败：保留原图 + WARN「疑似脏图」
```

### 10.3 UX

- 安检段「图片」：处理中 / 已替换 / 跳过并警告。  
- 报告：AUTOFIX「已去水印」或 WARN「未处理成功」。  
- **不在本设计做：** 大批量生活方式场景生成（属原清单 P2）。

## 13. 风险与约束

| 风险 | 缓解 |
|------|------|
| 兜底过激伤害购物体验 | 颜色分层；日志+工作台可改 |
| 动态 URL 打爆 Shopify | 短缓存、限流 |
| 安检动画与真实进度不一致 | 失败态强制对齐；不以动画冒充成功 |
| 敏感词误伤 | 先 WARN/可回滚文案；词表可配 |
| 去水印失败 | 不阻断生成；WARN |

---

## 14. 成功标准（本设计包）

1. 生成后 **不必先上 GMC** 就能看到红/黄问题与自动修补。  
2. 无尺码服装 Feed 含 `One Size`；无码商品 `identifier_exists=false` 且 brand 可读。  
3. 链接含 **真 variant id** + currency。  
4. GMC 可只配 **动态 URL** 拿到与规则一致的最新 Feed。  
5. 结果页三色灯文案正确；红灯需二次确认才「仍使用」。  
6. 抽屉可批量改均码/颜色；工作台只显示自动填。  
7. 敏感命中有日志；脏图有检测或处理路径。
