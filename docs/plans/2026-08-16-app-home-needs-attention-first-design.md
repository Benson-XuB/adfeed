# 2026-08-16 App Home「要处理优先」UX 设计

Field contract: docs/plans/2026-08-14-feed-field-contract.md  
North Star: docs/plans/2026-08-12-mvp-north-star.md

**状态：** APPROVED — 专家拍板已锁定；进入实现  
**范围：** 仅 App Home 信息架构与文案层级；**不改** Feed 字段主人、不静默品牌、不新开 Magic Bar / 安检大动画

## Locked decisions（UX 专家默认）

1. **第一屏数字：** 「要处理 N」为主数字；「已可投 M」小号并排（给掌控感，但不抢主）。「未进 Feed」仅在选品区提示，不上总览主数字。  
2. **首次生成：** 提供「全选当前列表并生成」；**禁止**静默全店自动生成。  
3. **主按钮：** 页头 primary = 生成/更新 Feed；有 Feed 后文案为「更新 Feed」。  
4. **排序：** 总览 → 要处理（主）→ Feed 链接（次）→ 本轮详情折叠 → 设置/选品/店铺警告。  
5. **流水线：** 仅生成中展开；完成后默认折叠。

## Goal

打开 App 的第一反应是：**「有 N 件要我处理」**，而不是「引擎跑完了 / 去复制链接」。  
商家掌控：先看问题商品 → 改或跳过 → 再更新 Feed。链接与技术细节降级。

对标：官方 Google & YouTube 的「商品状态」心智；差异化仍是 1688 脏色码/脏图/无码通道，但用商品语言呈现。

## Non-goals

- 不接 Google Content API「真常驻同步」（仍可 XML/CSV URL 交付）
- 不改 `title` / `color` / `pattern` / `brand` 字段主人逻辑
- 不做行内深度编辑器；改货以「在 Shopify 中编辑」+ 现有一件改色/码/换图为准
- 不把审查打分 / `g:*` 字段表推到第一屏

## Information architecture（打开后从上到下）

### 1. 总览条（一行）

- **要处理 N**（主数字，可点滚动到列表）
- **已可投 M**（次要）
- **未进 Feed K**（次要，仅有选品概念时）
- 右侧主按钮：无 Feed 时「生成 Feed」；已有 Feed 时「更新 Feed」

首次且从未生成：总览可显示「尚未生成」+ 主按钮，下方仍可空状态引导去选品（见 §4）。

### 2. 主舞台：要处理 N 件（默认展开）

分组（有则显示，无则省略整组）：

| 组 | 来源（现有能力） | 行内容 | 行动 |
|----|------------------|--------|------|
| 颜色需确认 | Multicolor 兜底 SKU | 缩略图 + 标题 + 规格 | 勾选 → 填色 → 一件应用；链到 Shopify |
| 尺码需确认 | One Size 兜底 SKU | 同上 | 勾选 → 填码 → 一件应用；链到 Shopify |
| 建议换广告主图 | I03 等 | 缩略图 + 标题 | 换广告图；链到 Shopify |
| 店铺门禁 | 品牌未确认 / 币种挡市场 | 短文案 | 确认品牌 / 去 Shopify 改币种 |

空状态（N=0 且已有 Feed）：一句「没有需要处理的商品」+ 次要「查看 Feed 链接」。

**原则：** 行首必须能认货（`s-thumbnail` + 标题）；禁止用规则号当主文案。

### 3. 已可交给渠道（默认折叠或次级卡片）

- 平台 × 市场 × 条数  
- URL + 复制  
- Limited / 说明一句  

有「要处理」时**不**抢第一屏视觉；N=0 时可略抬高。

### 4. 设置与选品（生成前 / 更新前）

保留但视觉降权：

1. 渠道 + 市场（记住上次）  
2. 商品表（图在前；勾选；在 Shopify 编辑）  
3. 店铺警告（品牌门禁保留；GTIN/COGS 仍折叠）

「更新 Feed」默认复用上次选品/渠道/市场；改设置后再点更新。

### 5. 永久降级

- 五步流水线：生成中可显示进度；完成后**默认折叠**  
- 优化日志、`g:*` 对照表、技术事件：默认折叠在「本轮详情」  
- 长 Intro：有过一次生成或品牌已确认后隐藏  

## 状态机（商家语言）

| 状态 | 定义（UI） | 数据大致来源 |
|------|------------|--------------|
| 要处理 | 需商家动作的商品/门禁 | Multicolor / One Size / I03 / 敏感需确认 / 品牌未确认 / 币种挡市场 |
| 已可投 | 已在最新 Feed 且无上述待办 | 有 feed 行且不在要处理集合 |
| 未进 Feed | 店内有货但未勾选进上次生成 | 商品表未选 ∩ 有目录 |

不承诺与 GMC 后台 Approved 一一对应（我们无 Content API 回写）；文案用「已可投 / 建议处理」，避免「已过 Google 审」。

## 主按钮文案

| 条件 | 按钮 |
|------|------|
| 无 Feed | 生成 Feed |
| 有 Feed，设置未改 | 更新 Feed |
| 有 Feed，要处理 > 0 | 更新 Feed（改完后再点；不强制先清零） |

商家可以**不处理**部分项就更新——掌控权：列表是建议，不是锁死门禁（品牌/币种等硬门禁除外，沿用现逻辑）。

## 验收（友好度）

1. 硬刷新后，有待办时第一眼是「要处理 N」，不是流水线或长说明。  
2. 待办行不看标题也能靠图认出商品。  
3. 复制 Feed 链接不超过一次展开/滚动到次级区。  
4. 三件真衣服（裤/裙/夹克）待办文案是人话，不是规则 ID。
