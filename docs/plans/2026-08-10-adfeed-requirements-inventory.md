## 4. 详细 UX 设计（来自你图片笔记 —— 此前遗漏的重点）

> 原则：**不弹窗打断主流程**；能过机的先过机；自动填的必须 **看得见、改得动、能批量**；红灯不叫「绿通」。

### 4.1 核心 Dashboard：「安检舱 / 安检流水线」（不是普通进度条）

**隐喻：** 像汽车出厂检测线，而不是转圈进度条。

**生成过程中 UI：**

1. 流水线式动画，依次「扫描」：  
   - 标题 Title  
   - 类目 Category  
   - 变体 Variants（颜色/尺码等）  
   - 标识 Identifiers（条码 / brand / identifier_exists）  
2. 每一步可显示微状态：通过 / 已自动修补 / 待确认  
3. **情绪文案示例（必须有价值感）：**  
   - 「AI 正在清洗你的 1688 脏数据，降低 GMC 拒审风险…」  
   - 「正在检查变体是否缺尺码/颜色…」  
   - 「正在开通无码通道（无 GTIN 商品）…」  

**生成结束后：**

- 顶部汇总：绿灯可提交 / 黄灯已兜底 / 红灯高风险（三色灯见第 8.4 节）  
- 一句话价值：「已自动修补 N 项 · 开通无码通道 · 请抽查黄灯项」  

---

### 4.2 核心交互：「AI 推荐 · 弹性确认」（两种场景）

#### 场景 A：源数据里有，但没映射到店（如 1688 标题里有「黑色 大码」）

| 项 | 设计 |
|----|------|
| 系统行为 | AI/规则解析标题与 HTML 描述，抽出 Color / Size 等 |
| 列表呈现 | 产品行内直接展示：`[图] → 颜色：Black（AI 提取）→ 尺码：Plus Size（AI 提取）` |
| 视觉 | **高亮**「AI 提取」标签（与人工填写区分） |
| 用户操作 | **默认不用点**；认为对就跳过 |
| 纠错 | **鼠标悬停** 出现快捷改：下拉/输入一键修正 |
| 禁止 | 不要用阻断式弹窗逼用户先点「确认全部」才能继续生成 |

#### 场景 B：源数据完全没有该属性

| 项 | 设计 |
|----|------|
| 系统行为 | 可选：视觉识别（如图片偏红 → 类服装）+ 文案失败后的官方兜底 |
| 列表呈现 | 不报错中断；商品仍生成，打 **黄色「AI 优化」标签** |
| 示例 | `[图] → 颜色：Red（视觉识别）→ 尺码：One Size（智能兜底）` |
| 用户感知 | 「任务完成了，只是有些是智能替代」而不是「失败了」 |
| 与报告关系 | 计入「自动处理 / 黄灯」列表，可进右侧抽屉批量改 |

**颜色抽取补充（笔记强调）：**

- 优先用 **大模型读标题+描述**（快、便宜、懂「军绿」→ Army Green）  
- 抽不到再 Multicolor / As Shown  
- 纯靠抠图认色作增强，不作唯一手段  

---

### 4.3 专家功能：「异常修正层」右侧常驻抽屉

**痛点：** 200 个商品里 50 个缺尺码，一个个点太慢。

| 元素 | 设计 |
|------|------|
| 位置 | 界面 **右侧常驻** Quick Drawer（异常修正层），不是一次性 Modal |
| 聚合 | **一键归类**：如「服装缺 size」「缺 color」「无码已开通」分桶 |
| 多选 | 桶内可多选 / 全选该桶 |
| Magic Bar（智能条） | 选中后顶部出现快捷操作： |
|  | · `[一键设为均码 One Size]` |
|  | · `[一键设为标准尺码表]`（若有预设 S–XXL） |
|  | · `[所选颜色全部改为：____]` 输入 Black 回车 → 50 条秒改 |
| 目标 | 最少点击让整店尽量「可提交」（黄灯清完或接受兜底） |

---

### 4.4 「微调工作台」：只看被自动填过的数据

| 项 | 设计 |
|----|------|
| 入口 | 生成成功后：「查看自动修补明细」/ 工作台 Tab |
| 表格内容 | **只显示被自动填充的字段行**（不是全店 152 行噪音） |
| 高亮 | One Size、Multicolor、AI 提取色等 **底色/标签高亮** |
| 操作 | 行内改；支持勾选后批量改（接 Magic Bar） |
| 同步 | 确认后再「写入 Feed / 刷新动态 URL」；未确认也可已生成（黄灯说明） |
| 价值展示 | 页头：「已为你自动修补 5 个缺尺码，并开通无码通道」 |

### 4.5 标题对比（投流专家可见价值）

| 项 | 设计 |
|----|------|
| 展示 | **原标题（1688/店内）** vs **Google 优化标题** 左右或上下对比 |
| 结构提示 | 说明目标结构：`[品牌] + [性别/年龄] + [品类] + [属性（色、码、材质）]` |
| 示例 | 原：一长串中文堆词 → 优：`eprolo French Vintage Floral Dress for Women - V-Neck, Red, One Size` |
| 位置 | 安检结果里可展开；工作台可按商品查看 |

### 4.6 优化日志（避免黑盒）

每条自动动作写进日志，生成后可展开，例如：

- 「已开通【1688 无码绿通】：`identifier_exists=false`，brand=…」  
- 「已自动修补 5 个缺尺码 → One Size」  
- 「已从标题提取颜色 Black × 12」  
- 「高风险 FATAL：无主图 × 2（仍写入 Feed，不建议直接提交 Google）」  

**禁止：** 全部静默完成后只给一个「成功」无明细。

### 4.8 与「不打断」相关的交互禁令

1. 不要因缺 size/color 弹 **阻断式**「必须先全部确认才能生成」。  
2. 不要把红灯结果标成「绿通 / 已过审」。  
3. 自动填必须可追溯（日志 + 高亮）。  
4. 批量改必须可撤销或再次生成覆盖（实现阶段定）。

## 5. 服装处理逻辑流程

```
输入商品（Shopify / 从 1688 导入）
  → 匹配 Google 商品类目（GPC）
  → 若是服装 / 鞋 / 配饰：
       size 空？ → 兜底 One Size（见第 8 节）
       color 空？ → 先文案抽取 → 再分层 Multicolor（见第 8 节）
       gender / age_group → 推断或默认
  → 否则：跳过服装专用变体规则
  → 全品类：
       condition 空则 = new
       类服装且 age_group 空 → adult
       无 GTIN → identifier_exists=false + 品牌策略（第 8 节）
  → 质量报告 + UX 三色灯 + 日志
  → 写 Feed（+ 动态 URL）
```

## 8. 专家结论（2026-08-10 已拍板）

### 8.1 尺码：默认 **`One Size`**（不用 OSFA 做对外默认）

- Feed 写 **One Size**；内部别名 OSFA/Free Size 可归一。  
- 原因：买家与广告更好懂。

### 8.2 品牌：可读品牌名，不用域名

1. App 配置品牌 → 2. 可读店铺名 → 3. `DEFAULT_STORE_BRAND`（如 eprolo）  
4. **禁止** `*.myshopify.com` 当 `g:brand`

### 8.3 缺颜色：禁止全体服装一刀切 Multicolor

1. 变体/标题/描述抽取（中→英）  
2. 仍空 → 黄灯警告，可生成  
3. 混色语义或完全失败 → Multicolor / As Shown  
4. 有真色绝不优先 Multicolor  

### 8.4 红灯仍出 Feed vs 绿通：三色灯叙事

| 灯 | Feed | 文案 |
|----|------|------|
| 绿 | 生成 | 可提交 Google |
| 黄 | 生成（含兜底） | 已自动补全，建议抽查 → 打开工作台 |
| 红 | **仍生成** | **不叫绿通**；主 CTA 处理问题；次 CTA 仍使用需二次确认 |

- 安检 = 流程跑完；绿通 = 仅无 FATAL。

## 9.5 图片对照查漏（第二轮回顾 —— 此前仍偏薄的部分）

对照你提供的多张笔记图，下列内容在初版/补 UX 版里曾被压缩或漏写，现强制补全：

### 9.5.1 五大能力赛道（市场定位原文结构）

笔记把工具拆成五条「可卖点」赛道，文档不能只写成一行摘要：

| 赛道 | 专业痛点 | 工具该干什么 |
|------|----------|--------------|
| **1. GMC 合规 / 防封** | 缺 GTIN、材质、性别等；文案误导 → 拒审/封号 | 导入或生成时 **AI 修补 + 自动预审**，提高过审率 |
| **2. 主图 / 视觉资产** | 1688 图有中文水印、牛皮癣字、廉价厂拍 → CTR 低 | **去中文水印/贴纸**；抠主体；生成偏高端的 **生活方式场景图**（服务 Google PMax） |
| **3. 短视频广告** | 拍 TikTok/Meta 素材贵、慢 | 详情图 **自动剪辑** + **英文字幕** + **西式配音（TTS）** |
| **4. 优质货源过滤** | 劣质 1688 货 → 高获客成本、差评 | 筛 **CE/FDA/RoHS** 或支持 **定制包装 / POD** 的厂；自动出「高质量/定制」向文案 |
| **5. B2B 批发模式** | 阶梯价难同步；批发意图难进广告 | 1688 阶梯价 → Shopify B2B 插件；批发词（bulk / wholesale）同步到 **Google 搜索广告**（不只 Shopping） |

### 9.5.2 投流权重与字段硬规则（笔记原话级）

- Google Shopping 权重心智：**标题 > 图片 > 价格**（标题重构优先级要体现这一点）。  
- **主图：** 清晰、偏白底；**严禁** 1688 水印与「牛皮癣」中文标签图直接进 Feed。  
- **价格：** 必须带币种（如 `19.99 USD`），且与 Shopify 落地页 **100% 一致**（已有币种设计，此处强调「金额也一致」）。  
- **availability：** 仅 `in_stock` / `out_of_stock` 两态（避免脏值）。  
- **材质 material：** 防封笔记与性别、GTIN 并列提及 → 诊断/可补字段，不能只写 color/size。  
- **3C / 汽配等：** 强调 `brand` + `gtin`/`mpn`；无码则走无码通道，不可假装有条码。

### 9.5.3 链接痛点（必须写进故事，不只写技术）

- 脏链接干扰 UTM。  
- **专业事故：** 广告点的是「蓝色 / M」，落地页默认成「红色 / S」→ 立刻跳出、浪费广告费。  
- 因此：**清洗垃圾后缀 + 强制真实 `variant=`** 是投放刚需，不是锦上添花。

### 9.5.4 敏感类目防火墙（要有举例与改写示例）

- **高发类：** 塑身衣、情趣内衣、战术刀、筋膜枪/按摩枪等灰产或敏感带。  
- **风险：** 1688 直译带攻击性/违禁词 → 触发 Adult / Prohibited → 拒审，严重可因 **Misrepresentation** 永久停用 GMC。  
- **工具动作：**  
  1. **关键词软化：** 如 `Tactical Combat Knife` → `Outdoor Camping Tool`（示例级，需词表可运营）。  
  2. **主动贴标：** 判定内衣等敏感 → Feed 注入 `adult=yes`（限流但护号）。  
- **数据时效：** 价/库存不同步 = 空点烧钱 → 与动态 Feed / 定时抓强绑定。

### 9.5.5 动态 Feed URL「降维」打法（笔记原结构）

面向专业投手的推荐形态：

1. **不要**只靠用户反复下载静态 CSV/XML 手传。  
2. 为每店生成唯一 **广告数据 Feed 链接**。  
3. Google 来拉时：后端读 Shopify **最新价与库存**，动态吐 XML。  
4. 用户只需把链接填进 GMC，设 **每日抓取**。  

**相对手传静态文件的优势（笔记「降维」）：** 少人工、库存价自动新、更符合代运营/投手工作流、与安检兜底逻辑在「出站渲染」时统一执行。

### 9.5.6 AI 角色定位

- 不是纯静默自动化，而是 **「AI 广告副驾驶」**：默认帮你补，但用黄灯/工作台让你能改。  
- 绿灯 = 格式与必填齐全；黄灯 = 用了兜底，建议抽查。
