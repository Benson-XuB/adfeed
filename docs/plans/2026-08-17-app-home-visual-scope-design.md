## 一、别人那套 AI 稿：哪里对、哪里毒

### 值得偷（结构清晰）

| 点 | 为什么好 |
|----|----------|
| 先定范围 → 再定市场 → 一个大 Create | 决策少，像向导 |
| 市场 Feed 卡片（国家 + 条数 + 复制） | 交付物一眼懂 |
| 店铺检查清单单独成块 | 和「商品问题」分开，不搅成一团 |

### 必须扔（看起来高级，其实不能用）

| 点 | 为什么毒 |
|----|----------|
| 「全部商品 (3)」只有类目卡片、**没有缩略图列表** | 你已经点破了：选了等于没选，认不出货 |
| 三个大数字 + **Readiness 60%** | 虚荣指标；商家不知道点哪；我们也不该编「过审率」 |
| 行内改 Google Title / **GTIN** | 违字段合同：不编条码；标题主人不在 App 行内乱叠 |
| 类目 Feed URL 按「服饰/美妆」切片 | MVP 我们是平台×市场一条 Feed，不是类目管道剧场 |
| 底栏 Ask anything | AI 聊天壳，不是商家作业 |

**一句话：** 那套稿「像仪表盘海报」，不是「能认货、能改、能交链接」的工作台。

### 我们现在为什么显得「水」

- 排序对了（要处理优先），但**选品仍像后台表格**：没有「范围卡片 + 预览条」的仪式感  
- 总览数字偏抽象，缺「当前选中的货长什么样」  
- Feed 卡片不够「市场货架」感（可偷别人的卡片，但排在要处理之后）

## 二、完美主路径（两态）

### 态 A — 还没有 Feed / 要重新生成（配置态）

自上而下 **只有三件事**：

```
① 选哪些货（必须看见图）
② 投哪里（渠道 + 市场）
③ 一个主按钮：生成 Feed
```

店铺门禁（品牌未确认 / 币种）用 **短 banner** 插在按钮上方，不另开长篇。

### 态 B — 已有 Feed（工作态，默认打开）

```
① 要处理 N（主舞台，图+标题）· 已可投 M（小）
② 店铺待办（清单，只列未过项）
③ 市场 Feed 卡片（复制链接）
④ 「调整范围并更新」折叠 → 回到态 A 的选品
```

流水线 / 技术详情 / 长 Intro：**永久降权**（生成中才展开进度）。

## 三、① 选品舞台（这次要做「不水」的核心）

### 3.1 范围条（不是抽象大方块 alone）

一行 chips（可多选逻辑简化为单选优先 MVP）：

- **全部在售**（默认）  
- **按类型**（Shopify `productType`，有几类出几个 chip；空类型归「未分类」）  
- 不做假「电子数码」演示类目；有真实类型才显示  

选中 chip 后：**下方立刻刷出商品预览**，不是只改数字。

### 3.2 商品预览（强制可视）

- **网格或表**：每格/行 **缩略图（`s-thumbnail` large）+ 标题 + 规格数**  
- 勾选框；顶栏：**已选 N / 本范围 M** +「全选本范围」+ 搜索  
- 空图：灰块占位，仍显示标题（比没图的纯文字表强）  
- **在 Shopify 中编辑** 链保留  

**验收：** 蒙住标题，只靠图也能说出「这是哪条裙子/裤子」。

### 3.3 不做什么

- 不做无图的「类目大卡」当唯一选品 UI  
- 不做行内 GTIN / 乱改广告标题  
- 不默认静默全店生成；「全选本范围」是显式动作

## 四、② 市场与 Create

- 渠道：Google / Meta / TikTok（现有）  
- 市场：多选；展示店币提示（现有币种门禁）  
- 主按钮文案：无 Feed → **生成 Feed**；有 Feed → **更新 Feed**  
- 按钮禁用条件沿用：未确认品牌 / 未选货 / 配额不够  

---

## 五、态 B 三块面板（偷别人的「三个数」，但换成真指标）

**禁止** Readiness %。改成可点、可行动：

| 面板 | 含义 | 点击 |
|------|------|------|
| **要处理** | 色/码/图/敏感 + 店铺门禁件数 | 滚到要处理列表 |
| **已可投** | 本轮 Feed 条数 − 要处理 SKU（近似） | 滚到 Feed 卡片 |
| **本范围已选** | 当前勾选商品数 | 展开选品 |

下面接：

1. **要处理列表**（图优先，一件改色/码/换图，可不清零就更新）  
2. **店铺待办**（合规 fail/warn、品牌、币种）— 只显示未完成  
3. **Feed 卡片**：每市场一张（平台徽章 · 国家 · 条数 · URL · 复制）

## 六、和「那套 AI 稿」的对照结论

| 维度 | 别人 AI | 我们完美稿 |
|------|---------|------------|
| 选品 | 类目卡，看不见货 | chip + **图库预览** |
| Create 后 | 虚荣三指标 + 链接 | **要处理** 主舞台 |
| 店铺检查 | 有，但位置飘 | 固定在要处理与链接之间 |
| 编辑 | 假 GTIN / Title 表 | Shopify 跳转 + 色码一件改 + 换广告图 |
| 多语言 | 展示向 | MVP 跟真实已生成市场走 |

---

## 七、实现边界（防又做成海报）

1. 仍用 Admin UI Extension + `s-*`（不迁自定义 CSS 仪表盘）  
2. 类型 chip 来自已加载商品的 `productType` 聚合  
3. 不新增 Feed 字段逻辑；不接 Content API  
4. 一次交付：选品可视 + 态 B 三面板真指标 + Feed 卡片排版；不做 Ask anything  

## 八、验收

1. 选「全部在售」或某一类型后，**不滚动也能看到至少 1 排缩略图**  
2. 生成后第一眼是「要处理 N」，不是复制链接、不是 60%  
3. Feed 按市场成卡片，复制一次完成  
4. 裤/裙/夹克在要处理列表里靠图可认
